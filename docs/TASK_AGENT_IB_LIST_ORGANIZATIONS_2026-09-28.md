# Задача агенту: команда `IB_LIST_ORGANIZATIONS` — организации базы с реквизитами

28.09.2026. От стороны сервиса стороне агента (агент кластера, способность `ib.admin`). Контракт —
[ONEC_AGENT_CLUSTER_CONTRACT.md](ONEC_AGENT_CLUSTER_CONTRACT.md), раздел «`IB_LIST_ORGANIZATIONS` — организации базы
с реквизитами»; формат реквизитов — [CONTRACT_BASE_REGISTRATION_2026-09-19.md](CONTRACT_BASE_REGISTRATION_2026-09-19.md),
«Реквизиты организаций в заявке».

## Зачем

В карточке базы («Управление 1С» → «Кластеры 1С» → база) появилась вкладка **«Организации»**. На ней видны:

- организации самой базы 1С с полным набором реквизитов;
- отметка «Основная» — организация, которую 1С подставляет по умолчанию;
- связь каждой организации со справочником «Организации» в ERP (по БИН). Если организации в ERP нет, администратор
  BuhProf создаёт её здесь одной кнопкой из реквизитов 1С.

Данные читаются так же, как пользователи и расширения базы: кнопка «Обновить» ставит команду агенту, агент входит в
базу, сервис кладёт ответ в свой кэш. Пока агент команды не знает, вкладка пуста, и панель пишет «Организации этой
базы ещё не читались у 1С».

**Почему агентом, а не расширением.** Вкладка должна работать и для баз без расширения БухПроф-AI, и без открытого
окна чата. Агент кластера входит в любую базу своего сервера служебным администратором ИБ, как для `IB_LIST_USERS`.

## Что уже сделано на стороне сервиса и панели

- Спецификация команды: READ, `ib.admin`, база обязательна, срок 900 с. Повторные запросы по одной базе склеиваются.
- Разбор ответа мягкий (`ai/src/onec/ibOrganizations.ts`). Реквизиты разбираются тем же кодом, что в заявке на
  подключение: длинное обрезается, мусор отбрасывается. Строка без наименования пропускается. Непустой список без
  единой организации не применяется — кэш остаётся прежним.
- Кэш — таблица `base_ib_organizations` (миграция 047). Ответ заменяет его целиком. Реквизиты, которых в ответе нет,
  остаются прежними.
- Связь с ERP сервис ищет по БИН при каждом показе, поэтому агенту ничего про ERP знать не нужно.
- Сборка без типа `IB_LIST_ORGANIZATIONS` при `ib.admin` показывается в карточке агента как «Нет в этой сборке:
  организации базы», а чтение отказывает `CAPABILITY_MISSING` ещё до постановки в очередь.

## Задачи

### А1. Команда `IB_LIST_ORGANIZATIONS` — главное

payload: `{ baseKey, auth? }`, как у `IB_LIST_USERS`. Ответ — `{ items: [...] }`, полный список:

```jsonc
{ "items": [
  { "id": "7f3c1a2e-5d4b-11ee-8c99-0242ac120002",   // УникальныйИдентификатор ссылки
    "name": "ТОО Nord Beer",                          // наименование, обязательно
    "bin": "180240037695",                            // БИН/ИИН; пустой не слать
    "main": true,                                     // только у основной (см. А2)
    "details": { /* формат заявки: legalName, kind, kbe, vat*, oked*, адреса, phones, emails, website,
                    director, chiefAccountant, bankAccounts — только заполненное */ } }
] }
```

Правила:

1. **Список полный**: все элементы справочника `Организации`, кроме помеченных на удаление. Права не сужать: агент
   входит служебным администратором ИБ. Частичный список сервис примет за «организаций стало меньше».
2. **Реквизиты** — по той же таблице источников, что в задаче расширению от 26.09
   ([TASK_EXTENSION_REGISTRATION_ORG_DETAILS_2026-09-26.md](TASK_EXTENSION_REGISTRATION_ORG_DETAILS_2026-09-26.md), Р1):
   `Справочник.Организации`, сведения по НДС на текущую дату, основной вид деятельности, контактная информация (БСП),
   ответственные лица на текущую дату, `Справочник.БанковскиеСчета` без помеченных на удаление. Если в базе стоит
   расширение `buhprof_api` с этим кодом, его можно вызвать через COM, а не писать чтение заново.
3. **Сбой чтения реквизитов одной организации не срывает список**: она уходит без `details`, причина — в журнал
   агента. Отказ всей команды — только если не удалось войти в базу или прочитать сам справочник.
4. Персональных данных сверх ФИО и должности не слать: ни ИИН руководителя, ни документов.
5. Пределы сервиса те же, что у заявки: строки до 500 знаков, телефонов и адресов почты до 10, счетов до 20.
6. Не вошли в базу — отказ с кодом входа (`IB_AUTH_FAILED`, `IB_CONNECT_FAILED`, …), как у `IB_LIST_USERS`.

### А2. Основная организация — `main: true`

Отметка только показывается в панели, менять её из панели нельзя: источник правды — 1С. Поле ставится у одной
организации — той, которую 1С подставляет по умолчанию в новые документы. Если организация в базе одна, `main` у неё.

**Вопрос к вам.** В «Бухгалтерии для Казахстана» основная организация — настройка пользователя, а агент входит
служебным администратором ИБ. Его личная настройка про базу ничего не говорит. Предлагаем порядок:

1. Одна организация (не помеченная на удаление) — она.
2. Есть значение, общее для базы (константа или настройка по умолчанию для всех пользователей), — оно.
3. Иначе `main` не слать ни у одной: «не знаем» честнее, чем личная настройка служебного пользователя.

Подтвердите этот порядок или предложите источник, который в конфигурации действительно общий для базы.

### А3. Объявление в сборке

Тип `IB_LIST_ORGANIZATIONS` — в перечне типов команд, при подтверждённом входе (`ib.admin`), вместе с остальными
командами внутрь базы. Без него сервис отказывает сразу, а панель подсказывает обновить агента.

### А4. Проверки

- База с одной организацией: `main` у неё, реквизиты полные.
- Многофирменная база: несколько организаций, `main` по порядку из А2.
- Организация без БИН, без банковских счетов, не плательщик НДС: поля не шлются, строка есть.
- Помеченная на удаление организация в ответ не попадает.
- Сбой чтения реквизитов одной организации: список уходит, у неё нет `details`.
- База без расширения `buhprof_api` — команда работает.
- Неверный пароль служебного администратора — `IB_AUTH_FAILED`.

## Как проверить вместе

1. Обновить агента кластера до сборки с `IB_LIST_ORGANIZATIONS`. В карточке агента пропадает «Нет в этой сборке:
   организации базы».
2. Карточка базы → «Организации» → «Обновить». Операция видна в «Прогрессе запросов и команд». После неё в таблице
   организации с реквизитами, у основной отметка «Основная».
3. У организации, которая есть в ERP, в колонке «Организация ERP» ссылка на её карточку. У отсутствующей — «нет в
   ERP», и администратор BuhProf может создать её кнопкой «Создать организацию».
4. Пометить организацию на удаление в 1С и снова «Обновить» — строка пропадает.
