## Часть 1. Регистрация базы (канал «чат внутри 1С»)

ЗАЧЕМ. Сейчас токен базы выпускается CLI `npm run base-token -- issue` и копируется в 1С руками. Нужна регистрация
в два нажатия: администратор базы отправляет заявку из 1С, администратор BuhProf одобряет её в панели,
токен приходит в 1С сам и нигде не показывается.

### `POST /v1/onec-chat/register` — заявка (без токена)

Лимит: не больше 5 заявок в час с одного IP и одной базы (`base.id`).

```jsonc
{
  "base": {
    "id": "uuid",                 // идентификатор ИБ (БСП: СтандартныеПодсистемыСервер.ИдентификаторИнформационнойБазы)
    "name": "Бух_ТОО_Альфа",       // Ref для серверной базы, имя каталога для файловой
    "kind": "server | file",
    "server": "srv-1c",            // только для server
    "configuration": { "name": "БухгалтерияДляКазахстана", "synonym": "…", "version": "3.0.44.1" },
    "platform": "8.3.25.1257",
    "extensionVersion": "1.5.0",
    "computer": "SRV-1C"           // имя компьютера, где выполнился запрос (сервер 1С)
  },
  "organizations": [ { "id": "uuid", "name": "ТОО Альфа", "bin": "123456789012" } ],
  "user": { "id": "uuid", "name": "Администратор" },     // кто отправил заявку в 1С
  "contact": "Иванова А., +7 701 000 00 00",             // свободный текст: с кем связаться
  "comment": "подключаем с 1 октября"
}
```

Ответ `data`:

```jsonc
{
  "registrationId": "uuid",
  "code": "K7M-42Q",               // короткий код: его называют по телефону и ищут в панели
  "pollSecret": "base64url, 32 байта",   // только ASCII; знает только эта база
  "expiresAt": "2026-09-26T12:00:00Z",   // заявка живёт 7 дней
  "pollAfterSecs": 10
}
```

Повторная заявка той же базы (`base.id`), пока прежняя не решена, возвращает **ту же** заявку (тот же код).

### `GET /v1/onec-chat/register/:registrationId` — решение

Заголовок `X-Registration-Secret: <pollSecret>`. Неверный секрет — `404` (не выдавать, что заявка есть).

```jsonc
{
  "state": "PENDING | APPROVED | REJECTED | EXPIRED",
  "code": "K7M-42Q",
  "note": "причина отказа или комментарий администратора",
  // ТОКЕН — только при APPROVED и только ОДИН раз, при первом опросе после одобрения; дальше поля нет:
  "token": "bpb_…",
  // База и организация приходят при КАЖДОМ опросе после одобрения (уточнено 21.09): их незачем запоминать,
  // а форме 1С они нужны, чтобы показать, куда её подключили.
  "base": { "key": "Бух_ТОО_Альфа", "name": "…" },
  "organization": { "uuid": "…", "name": "…" }     // организация ERP, к которой привязана база
}
```

Токен выпускается прежним `BaseTokenStore.issue` в момент первой выдачи. Если 1С не забрала токен (сеть
оборвалась), администратор повторяет заявку — старый неполученный токен отзывается.

### `POST /v1/onec-chat/revoke` — база отключается сама

С `X-Base-Token`: отозвать токен этой базы (`BaseTokenStore.revoke`, кто — «1С: <user.id>»). Вызывается кнопкой
«Отключить базу» в 1С до того, как токен стирается там; ответ `{revoked: true}`. Без этого стёртый в 1С токен
оставался бы действующим на сервисе (аудит РС10).

### Панель (ПН)

- «Заявки на подключение»: код, база, конфигурация, организации с БИН, компьютер, кто отправил, контакт,
  комментарий, время. Поиск по коду.
- «Одобрить»: выбрать организацию ERP (по умолчанию — чей БИН совпал с организацией базы), ключ базы в
  реестре (по умолчанию `base.name`); «Отклонить» с причиной.
- В карточке базы — её токены (кем выпущен, когда, отозвать) — то, что сейчас только в CLI.

### Сторона 1С (сделано, расширение 1.5.0)

Форма «БухПроф AI → Подключение к BuhProf AI»: адрес сервиса, «Отправить заявку» (контакт, комментарий),
код заявки крупно, автоматическая проверка решения раз в 10 с, пока форма открыта, и кнопка «Проверить
решение»; запасной путь — «Токен вручную»; «Проверить связь»; «Отключить базу» (стирает токен).
Секрет заявки и токен — в безопасном хранилище БСП, в интерфейсе не показываются.

## Часть 2. Активация БИНов бизнес-агента

ЗАЧЕМ. Лимит «первые N БИНов по порядку» зависит от порядка баз и организаций в настройках агента: поменяли
порядок — сменились обслуживаемые организации. Нужна явная активация: какие БИНы обслуживаются, решает
администратор BuhProf по запросу клиента.

### Агент → сервис: в теле heartbeat

```jsonc
"activationRequests": [ { "bin": "123456789012", "name": "ТОО Альфа", "baseKey": "Бух_ТОО_Альфа",
                          "comment": "…", "requestedAt": "2026-09-19T16:40:00+05:00" } ]
```

Поле приходит, пока запрос не принят (агент удаляет его у себя после успешного heartbeat). Повтор того же БИНа
— не новый запрос, а обновление прежнего.

### Сервис → агент: в ответе register и heartbeat

```jsonc
"limits": { "maxBases": 5, "maxBins": 10, "activeBins": ["123456789012", "…"] },   // activeBins — НОВОЕ
"activation": [ { "bin": "123456789012", "state": "PENDING | APPROVED | REJECTED", "note": "…", "decidedAt": "…" } ]
```

- `activeBins` есть → агент обслуживает **ровно эти** БИНы (`maxBins` для сведения); нет → прежнее правило
  «первые `maxBins` по порядку». Команда по БИН вне списка — `LICENSE_LIMIT` «не активирована, запросите
  активацию».
- `activation` — решения по запросам этого агента (последние 90 дней); агент показывает их в окне.

### Панель (ПН)

- «Запросы активации БИНов»: агент, база, организация, БИН, комментарий, время; «Одобрить» (БИН добавляется в
  `activeBins` агента; если превышает `maxBins` — предупредить) / «Отклонить» с причиной.
- В карточке агента — список активных БИНов с «Отключить».
- Переход: у агента без `activeBins` кнопка «Зафиксировать текущие» — записать в список БИНы, которые сейчас
  обслуживаются по правилу «первые N».

### Сторона агента (сделано)

Окно агента, вкладка «Базы и БИНы»: таблица «база — организация — БИН — статус» (Активен / Не активен /
Запрос готовится к отправке / Отправлен / На рассмотрении / Отклонён: причина / База сверх лимита / База
недоступна), «Запросить активацию» по строке и «всех неактивных», комментарий к запросу, «Проверить базы
сейчас», редактор дополнительных баз (веб-сервер, файловая база, сервер 1С в сети).
