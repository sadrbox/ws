## Что на самом деле было в «Ошибка при работе с файлом» (16:03 UTC)

Воспроизведено на копии `Dev_01` (файловая база, `ibcmd` 8.3.25.1257):

1. Без учётной записи базы `ibcmd` **не отказывает, а спрашивает «Имя пользователя:» с консоли — бесконечно**
   (3,6 МБ повторов за 20 с). Агент держал stdin закрытым, ждал предельные 180 с и брал это за пустой
   список. Отсюда 3 минуты на каждой попытке.
2. Ключи `--user`/`--password` в режиме `extension` `ibcmd` **не принимает** («Ошибка разбора параметров»), в
   режиме `config` **молча пропускает** и всё равно спрашивает. Учётная запись работает только ответом в
   stdin (`имя\nпароль\n`) — во всех режимах.
3. Сам файл цел: тот же `buhprof_api.cfe` 1.8.3 через `ibcmd config load` + `config apply` с учётной

   контекста — у сборки 25.09 в отказе не было ни шага, ни файла. Теперь есть, и путь для базы кластера
   другой.

## Почему `CLUSTER_LIST_SESSIONS {baseKey}` возвращал `items: []`

Отбор верный: ключ базы приводится к нижнему регистру и ищется среди баз кластера, `rac session list
--cluster=… --infobase=<uuid>` идёт в тот кластер, где база лежит; по приложению ничего не фильтруется —
фоновое задание в списке видно как сеанс `BackgroundJob`, **пока оно выполняется**. Базу же держит не
сеанс, а **соединение рабочего процесса с СУБД** (`rac connection list --infobase`): оно живёт после
ухода сеансов и завершения заданий, и именно оно не пускало `ibcmd` 16.09 («приложение: Фоновое задание»
в тексте блокировки — это держатель соединения). Поэтому:

- агент перед `ibcmd` теперь проверяет и соединения (`CLUSTER_LIST_CONNECTIONS {baseKey}` — команда есть);
- для базы кластера это уже не важно: расширение идёт через COM, а он монопольного доступа не требует.

Подготовку сервиса (запрет заданий → закрытие входа → снятие сеансов) оставляйте: она нужна для
выгрузки/загрузки `.dt`, а расширению не мешает.

## `IB_EXPORT_EXTENSION`

- COM: `Найти(имя)` → `ПолучитьДанные()` → `Записать(файл)` во временный каталог агента → файл в base64
  в ответе; `ibcmd config save --extension` — запасной путь при невозможном входе.
- Предел файла **3,5 МБ** (тело ответа сервису 5 МБ с base64); больше — `IB_ERROR` с размером и советом
  забрать файл с сервера.
- Имя в ответе — фактическое из базы (регистр может отличаться от запрошенного), `fileName` = `<имя>.cfe`.
- **Не проверено на живом кластере**: COM-путь выгрузки проверен только чтением кода и юнит-тестами ответа
  (файл → base64, пустой/отсутствующий файл → отказ); `ibcmd config save` — по справке утилиты. Первый
  живой вызов из панели покажет.
