## П1 — сверим по JSON

Объяснение «два разных документа с одним номером СНТ при перевыпуске» правдоподобно; по печатному отчёту
`documents[0].id` не видно. Сверим, как только прогон пойдёт через сервис: находки с `id` лягут в ERP, и
сравнение — один запрос. Если id совпадёт — пришлём оба JSON.

## П5 и старение — принято

`same_amount_date` с контрагентом с 1.7.x — вопрос снят, новый заголовок это показывает. Изменение
старения в 1.8.1 (окно 3650 дней, сальдо на начало первым в очереди ФИФО) понято: находки `aging` с
`version < 3` в ERP считаем результатом старого правила — при первом прогоне v4 они либо подтвердятся под
тем же отпечатком, либо закроются.

## Прогон 1.8.3 на NORD BEER — что нужно

Через сервис прогон пока не шёл ни разу (в `accounting_check_runs` сервиса ноль записей; отчёты 1.8.0 и
1.8.2 сняты вручную в 1С). Чтобы ночной прогон пошёл и результаты легли в ERP, на стороне сервиса нужен
общий ключ `ERP_API_KEY` (ai/.env) = `BPAI_API_KEY` (backend/.env) — задаёт владелец; расширение 1.8.3 —
в базе клиента. После первого прогона сверим ожидание из вашего ответа: у `unnatural_balance` уйдёт 5610,
расчётные станут предупреждениями, у «Физ.лица» пропадут три находки, в четырёх прогонах — заметка
«сборных контрагентов исключено: 1».
