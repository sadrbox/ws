## Целевая модель

    источник ──► notify() / useReportNotice() / startOp() ──► ОДНО хранилище ──► показы
                                                               │
                                     ┌─────────────────────────┼──────────────────────┐
                                     ▼                         ▼                      ▼
                               тост (секунды)        область «сообщения»      полоса/спиннер
                                                     (история, срезы)         (идущая работа)

Три вида записи в одном хранилище:

| Вид | Пример | Живёт | Кто снимает |
|---|---|---|---|
| `state` | «не заполнен склад» | пока источник сообщает | источник |
| `event` | «нет связи», «импорт: 12 из 100 не удалось» | до очистки / срока хранения | человек |
| `operation` | «проверка 40 баз · 60 %» | пока идёт; завершённая до очистки | человек |

Тост — не источник и не хранилище, а КОРОТКИЙ ПОКАЗ события. Событие, которое не должно
оставлять следа, помечается явно (`ephemeral`), а не тем, что автор позвал `showToast`.

### M10. Единая точка входа `notify()` (P0) — СДЕЛАНО 2026-09-13

Итог: `notify` в `TechMessages/store.ts`; `noteNotice`, `addMessage`, `addPaneNotification`,
`routeError`/`reportError` — обёртки над ним; `showToast` получил `title`, прямой
`dispatchEvent("ui_toast")` в `paneNotifications` убран. Попутно: системная ошибка формы в
пейне давала ДВА одинаковых тоста (`useFormStore.setError` + уведомление панели) — теперь
один. Тест — `__tests__/notify.test.ts`. Параметр `key` отложен в M16: без склейки он
ничего не делает.

Сделать в `components/TechMessages/store.ts` одну функцию для событий:

    notify({
      severity: "error" | "warning" | "attention" | "info" | "success",
      text: string,
      source: string,
      scope?: string,            // по умолчанию APP_SCOPE
      ref?: { endpoint, uuid, label? },
      actions?: [...],
      key?: string,              // склейка повторов, см. M16
      toast?: string | false,    // короткий текст тоста; false — без тоста; по умолчанию text
      ephemeral?: boolean,       // только тост, без записи в журнал
    }): string

`noteNotice`, `addMessage` и тост внутри `addPaneNotification` становятся тонкими
обёртками над `notify` (имена сохранить: у них живые потребители и тесты). `showToast` из
`components/UIToast` для прикладного кода остаётся только как `notify({ ephemeral: true })`.
Прямой `window.dispatchEvent("ui_toast")` в `hooks/paneNotifications.ts` — последний, убрать.

`routeError` / `reportError` переписать на `notify`: логика выбора канала не меняется.

`useReportNotice` / `reportNotices` (вид `state`) не трогать: у них другой жизненный цикл.

*Готово, когда:* в `store.ts` один путь создания события; `ui_toast` отправляется только
из `components/UIToast` (`showToast`), прямых `dispatchEvent("ui_toast")` в прикладном
коде нет; тест: `notify` без `ephemeral` даёт и тост, и запись; с `ephemeral` — только
тост; `toast: false` — только запись.

### M16. Защита от шума: склейка повторов и предел частоты (P2, после M10) — СДЕЛАНО 2026-09-13

Итог: `notify({ key })` — повтор в окне 60 с правит ту же запись (`repeat`, строка «×N»),
тост о повторе молчит до конца окна; ключ отделён от ключей живых источников. Сетевые
уведомления `useFormStore` идут с `NETWORK_KEY`, `dismissNetworkNotifications` снимает по
ключу (`dismissByKey`) — заодно снимается «Сервер временно недоступен», которого прежняя
регулярка не знала. `services/syncManager.ts` в журнал не пишет (только своё состояние) —
трогать не понадобилось.

Состояния (`reportNotices`) склеиваются по ключу, события — нет: у `noteNotice` ключ
`once_N`, у `addMessage` ключ равен id. «Нет связи с сервером» шлют независимо
`hooks/useFormStore.ts` (два места, на каждый пейн) и `services/syncManager.ts`; при
опросе раз в 3 с журнал заполняется одинаковыми строками и вытесняет полезное из
`LIMIT = 200`.

Правило в `notify`: событие с тем же `scope + key` в течение окна (например 60 с) не
создаёт новую запись, а обновляет `lastAt` и увеличивает `repeat`; строка показывает
«×N». Тост при склейке не повторяется чаще раза в окно. Для сетевых сообщений задать
общий ключ `network` — тогда `dismissNetworkNotifications` можно перевести с регулярного
выражения по тексту (`NETWORK_RE`) на ключ.

*Готово, когда:* тест: десять `notify` с одним ключом за секунду дают одну запись с
`repeat: 10` и один тост; `dismissNetworkNotifications` не разбирает текст.

## Открытый вопрос: название области

«Технические сообщения» после M13 показывает три вида записей, из которых «техническими»
не являются ни ошибки валидации, ни итоги работы. Предложение — «Сообщения» (привычно по
1С и покрывает все три вида). «Протокол событий» не подходит: состояние формы и идущая
операция событиями не являются, «протокол» обещает неудаляемость, а рядом уже есть
«События 1С» и журнал регистрации 1С. Решение за владельцем продукта; переименование —
ключ `techMessages` (RU/KK) в `translations.json`.
