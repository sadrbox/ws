# Задача агенту: договоры организаций и наименование счёта в `IB_LIST_ORGANIZATIONS`

[TASK_AGENT_IB_LIST_ORGANIZATIONS_2026-09-28.md](TASK_AGENT_IB_LIST_ORGANIZATIONS_2026-09-28.md): команда та же, новый
блок реквизитов — `details.contracts`.

**Статус: принято.** Агент сделал Д1 и Д3 в сборке **2026-09-28 18:27** ([ANSWER_AGENT_IB_ORG_CONTRACTS_2026-09-28.md](ANSWER_AGENT_IB_ORG_CONTRACTS_2026-09-28.md)); формат совпал с разбором сервиса. Сервис прописал её эталоном (`AGENT_LATEST_BUILD`), панель не повторяет название блока, если агент уже назвал его в записке (`договоры: …`). Осталось поставить сборку агенту кластера и проверить на живой базе.

## Зачем

Строка вкладки «Организации» карточки базы открывается карточкой **«Организация базы 1С»**. У неё есть вкладки
«Банковские счета», «Договоры», «Контактные лица» и «Контакты». В каждой строке — реквизиты из 1С текстом и поле-ссылка
на объект ERP, найденный автоматически. Для договора это «Договор» ERP той же организации: сервис и панель ищут его по
номеру договора и БИН контрагента.

Счета, ответственные лица и контакты агент уже присылает. Договоров в ответе нет, поэтому вкладка «Договоры» пуста. Пока
их нет, панель пишет, что агент договоры ещё не читает.

## Что уже сделано на стороне сервиса и панели

- `details.contracts` разбирается мягко, как прочие реквизиты (`ai/src/bases/orgDetails.ts`). Строки обрезаются, мусор
  отбрасывается. Повторы убираются по ссылке 1С, без неё — по наименованию, номеру и контрагенту. Предел — 500
  договоров на организацию.
- Кэш — тот же `base_ib_organizations.details` (jsonb). Миграция не нужна.
- Записка с `block: "contracts"` сохраняет прежние договоры, как и для остальных блоков. Если блок прочитан и пуст,
  договоров в 1С больше нет, и кэш их тоже теряет.
- Старый агент поля не шлёт, и ничего не ломается: список просто пуст.

## Задачи

### Д1. `details.contracts` — договоры организации

Источник — `Справочник.ДоговорыКонтрагентов` с отбором `Организация = <эта организация>`. Помеченные на удаление не
брать. Порядок — от новых к старым по дате договора. Предел — 500 на организацию: сервис отбросит лишнее, но
передавать тысячи строк незачем.

```jsonc
"details": {
  // … прежние реквизиты …
  "contracts": [
    { "id": "5b1e…",                        // УникальныйИдентификатор ссылки
      "name": "Договор поставки № 15/24",   // Наименование, обязательно (или number)
      "number": "15/24",                    // НомерДоговора, если реквизит есть
      "date": "2024-01-15",                 // ДатаДоговора, ГГГГ-ММ-ДД
      "validUntil": "2025-12-31",           // СрокДействия, если задан
      "kind": "С поставщиком",              // ВидДоговора — представление, как в 1С
      "currency": "KZT",                    // ВалютаВзаиморасчетов — буквенный код
      "counterparty": {                     // Владелец договора
        "id": "a9c0…", "name": "ТОО Бета", "bin": "990140000123" } }
  ]
}
```

Правила:

1. Пустые поля не слать. Если реквизита в конфигурации нет (например, `НомерДоговора`), поле опускается.
2. БИН/ИИН контрагента берётся из его реквизита. Если БИН пуст, `bin` не слать: по наименованию сервис договор не
   связывает.
3. Сбой чтения договоров не срывает ответ. Тогда организации уходят без `contracts` и с запиской
   `{ "block": "contracts", "message": "<причина>" }` в корне ответа, как у блоков `contacts`, `responsible`,
   `bankAccounts`.
4. Договоры читаются одним запросом на базу для всех организаций, а не отдельным запросом на каждую.
5. Персональные данные сверх наименования и БИН/ИИН контрагента не слать.

### Д3. Наименование банковского счёта — `bankAccounts[].name`

Во вкладке «Банковские счета» карточки «Организация базы 1С» первая колонка — «Наименование» счёта. Сейчас агент его
не присылает, и панель показывает вместо него название банка. Нужно добавить к каждому счёту поле `name` —
`Наименование` элемента `Справочник.БанковскиеСчета`, до 300 знаков, пустое не слать. Сервис это поле уже принимает
(`ai/src/bases/orgDetails.ts`). «Создать организацию» переносит его в наименование банковского счёта ERP.

### Д2. Сообщить сборку

В ответе на эту задачу укажите сборку агента, в которой появились договоры. Сервис способность не проверяет: поле
либо есть, либо нет.
