# План: развитие расширения buhprof_api

22.09.2026. Сторона 1С. Парный план для панели и сервиса —
[PLAN_ONEC_CAPABILITIES_2026-09-22.md](PLAN_ONEC_CAPABILITIES_2026-09-22.md).

## Откуда взялись задачи

Сейчас шлюз умеет 25 операций: реализации, поступления, счета, акт сверки, банк (импорт, проведение, сверка по
1030), печать, отчёты файлом, поиск по четырём справочникам, стендовые операции. Разрывы:

1. Документ читается только по идентификатору — **списков нет**.
2. Справочники **только читаются**: нет контрагента — диалог упирается в тупик.
3. Отчёты возвращают **файл**, а не числа: сравнить и сложить нельзя.
4. **Касса** не покрыта вовсе, хотя это ежедневная работа.
5. Проблемы подключения выясняются по частям — **нет самопроверки**.

## Состояние на 22.09, вечер

РБ1–РБ9 реализованы, версия расширения — 1.6.0. На базе `Dev_01` расширение ещё **не загружалось**:
проверены статический контроль (`tools/static_check.py`, 32 модуля, 37 обработчиков HTTP) и все тексты
запросов — они выполнены на живой базе через COM до написания кода, вместе с именами документов,
реквизитов и перечислений.

Новые операции шлюза: `documents.list`, `documents.types`, `counterparties.create`, `products.create`,
`analytics.debts`, `analytics.balances`, `analytics.turnovers`, `cash.create`, `cash.get`, `cash.post`,
`cash.unpost`, `diagnostics`. Команды для агента и формы чата: `LIST_DOCUMENTS`, `LIST_DOCUMENT_TYPES`,
`CREATE_COUNTERPARTY`, `CREATE_PRODUCT`, `GET_DEBTS`, `GET_BALANCES`, `GET_TURNOVERS`,
`CREATE_CASH_ORDER`, `GET_CASH_ORDER`, `POST_CASH_ORDER`, `UNPOST_CASH_ORDER`, `SELF_CHECK`.

Два имени пришлось поправить по факту базы: ставка НДС — **справочник** `СтавкиНДС`, а не перечисление;
единица номенклатуры — `БазоваяЕдиницаИзмерения`. У акта сверки нет `СуммаДокумента`, в списке она
приходит нулём.

## Задачи

**РБ1. Списки документов.** Операция `documents.list`: вид документа (реализация, поступление, счёт, ПКО, РКО),
период, контрагент, организация, признак проведения, предел. Возвращает номер, дату, контрагента, сумму,
проведён ли, идентификатор — то, по чему документ узнают и на что потом ссылаются.

**РБ2. Создание контрагента.** `counterparties.create`: БИН, наименование, вид (юрлицо или ИП). БИН
обязателен — по нему контрагент ищется и не двоится. Повторный вызов с тем же БИН возвращает существующего, а
не создаёт второго.

**РБ3. Создание номенклатуры.** `products.create`: наименование, вид (товар или услуга), единица измерения,
ставка НДС. Дубли по наименованию не плодятся: точное совпадение возвращает существующую позицию.

**РБ4. Задолженность.** `analytics.debts`: по счетам расчётов (1210, 3310 и авансы) на дату — кто должен нам,
кому должны мы, с разбивкой по контрагентам и суммой. Числа, а не печатная форма.

**РБ5. Остатки.** `analytics.balances`: остатки на дату по кассе (1010), банковским счетам (1030) и расчётам,
с расшифровкой по субконто.

**РБ6. Обороты.** `analytics.turnovers`: обороты за период по счёту с разрезом по контрагентам или статьям.

**РБ7. Касса.** `cash.create` (приходный и расходный ордера), `cash.post`, `cash.unpost` — по образцу
реализаций: заполнение типовыми механизмами, проведение отдельной операцией, идемпотентность по `requestId`.

**РБ8. Самопроверка.** `diagnostics`: связь с сервисом, наличие и годность токена, права текущего пользователя,
организации с заполненным БИН, версия расширения, доступность нужных объектов конфигурации. Одним ответом —
список проверок с отметками и подсказками.

**РБ9. Версия и совместимость.** Поднять `ВерсияAPI` до 1.6.0; сервис по ней решает, показывать ли модели новые
инструменты (СВ17 в парном плане).

## Правило, которое сохраняется

**Разносит 1С, а не API.** Каждая новая операция вызывает типовые механизмы конфигурации (заполнение,
проведение, расчёт НДС), а не повторяет их правила своим кодом. Так обновление типовой не ломает расширение —
как это уже сделано с банковской выпиской через обработку «Клиент-банк».

## Что остаётся за пределами этого плана

- **Стыковка с ЭСФ** (`buhprof_esf`): выписка счёта-фактуры следом за реализацией. Требует правок во втором
  расширении — отдельное решение.
- **Склад, возвраты, авансовые отчёты, закрытие месяца** — следующие участки учёта, после кассы.
- **Абстракция над конфигурацией** (работа не только с БК КЗ) — продуктовое решение: пока продажи идут в
  пределах БК, слой совместимости удорожает каждую операцию вдвое.
