# План: встроенный чат AI-помощника в 1С (расширение buhprof_api)

> **Заменён 19.09.2026** утверждённым планом [PLAN_BUHPROF_API_2026-09-19.md](PLAN_BUHPROF_API_2026-09-19.md): архитектура уточнена (две роли агента, чат выполняет команды в сеансе пользователя, многобазовый бизнес-агент), этапы чата вошли в новый план. Этот документ — история рассуждения.

19.09.2026. Цель — бухгалтер работает с AI-помощником прямо в 1С: выбирает организацию, пишет команды
обычными словами, прикладывает PDF (выписки, накладные), подтверждает действия кнопками, открывает созданные
документы, печатные формы и отчёты в самой 1С.

## Что уже есть и переиспользуется

| Готово | Где |
|---|---|
| Чат с выбором организации, подтверждения (карточки), история диалогов | `ai/src/http/chatRouter.ts`, `ai/src/chat/workflow.ts` |
| PDF-вложения: до 3 файлов, до 20 МБ, распознавание выписки в фоне, состояние `PROCESSING`, опрос истории | `chatRouter.ts:46-100`, `ai/src/bank/extract*.ts` |
| Инструменты модели по белому списку, защита от выдуманных id, CRITICAL-подтверждения | `ai/src/tools/registry.ts`, `chat/prompt.ts` |
| Выполнение операций в 1С: 25 маршрутов, идемпотентность, типовые механизмы | расширение `buhprof_api`, агент `bpapi_agent` |
| Файлы результатов (печать, отчёты) с временем жизни | `ai/src/files/store.ts`, `GET /v1/files/:id` |

**Чего нет:** входа в сервис для пользователя 1С (сейчас только JWT пользователя ERP, `ai/src/auth/index.ts`),
формы чата в 1С и показа результатов средствами 1С.

## Архитектура

```
Форма «БухПроф AI» в 1С (расширение)
   │ HTTPS с сервера 1С: токен базы + пользователь 1С + БИН организации
   ▼
AI-сервис: канал «база 1С» → тот же ChatWorkflow → модель → инструмент
   │                                                    │
   │  вариант А (MVP): команда в очередь → агент → HTTP → та же база, от имени bpapi
   │  вариант Б (этап 5): инструмент возвращается в 1С и выполняется там, под правами пользователя
   ▼
Ответ / карточка подтверждения / файл / ссылка на документ → форма
```

**Непреложные решения:**
1. **Модель вызывает только сервис.** Ключ LLM в базу 1С не попадает никогда (см. аудит E1).
2. **Токен базы для чата — отдельный от токена API**, хранится в безопасном хранилище БСП, в сервисе — хэшем.
3. **Организация — контекст каждого хода.** Сервис подставляет БИН выбранной организации в каждый инструмент;
   список организаций в форме строится запросом с `РАЗРЕШЕННЫЕ` под пользователем 1С — чужую не выбрать.

**Решение, которое нужно принять — как выполнять команды:**

| | Вариант А: через агента (MVP) | Вариант Б: локально в 1С |
|---|---|---|
| Работы | мало: сервис и агент без изменений в пути исполнения | много: новый протокол «инструмент выполняет клиент» |
| Нужен агент | да, на связи | нет |
| Под чьими правами | `bpapi` (полные права) — ограничение только организацией и белым списком | **пользователя 1С** — RLS и ограничения типовой действуют |
| Скорость | плюс круг «сервис → агент → 1С» | быстрее |

Рекомендация: **А для первого выпуска, Б — этапом 5.** Б закрывает главный риск встроенного чата: через чат
бухгалтер с урезанными правами не должен уметь больше, чем в самой 1С.

## Этапы

### Этап 0. Подготовка (расширение, сервис)
- Аудит расширения: E1 (секреты в каталоге), E2 (стендовая операция), E6 (`errorId` у 500).
- Контракт канала 1С: маршруты, заголовки, ответы — раздел в `ONEC_AGENT_CLUSTER_CONTRACT.md` или отдельный файл.

### Этап 1. Канал «база 1С ↔ сервис» (сервис)
- Субъект «пользователь 1С»: `X-Base-Token` (токен базы) + `X-1C-User` (UUID и имя пользователя ИБ). Токен
  выпускается в панели администрирования для базы, в сервисе хранится хэшем, отзывается.
- Привязка: база → организация ERP → бизнес-агент (для варианта А). Таблица привязок и миграция.
- Маршруты: `POST /v1/onec-chat` (схема как у `/v1/chat` плюс `organizationBin`), `GET /v1/onec-chat/conversations`,
  `GET …/conversations/:id`, `GET /v1/onec-chat/files/:id`.
- Диалог принадлежит паре «база + пользователь 1С»; аудит с каналом `1c`.
- Лимиты на пользователя 1С (как у ERP: 30 ходов и 6 вложений в минуту).
- Промпт: организация хода задаётся БИНом из 1С и подставляется в инструменты; вопрос «какая организация?»
  модель больше не задаёт.
- **Готово, когда:** e2e-скрипт от имени «пользователя 1С» проходит сценарии нынешних `chat-e2e`.

### Этап 2. Форма чата в расширении — MVP (расширение)
- Общая форма `BPAPI_Чат`: выбор организации, лента сообщений (форматированный документ), поле ввода,
  «Отправить», история диалогов. Команда открытия — в разделе и в глобальных командах.
- Настройки: адрес сервиса, токен базы (безопасное хранилище БСП), проверка связи. Форма настроек — только
  администратору.
- HTTP к сервису — с сервера 1С (`HTTPСоединение`, TLS, прокси из настроек БСП, таймауты). Если расширение
  стоит в безопасном режиме — запрос разрешения на внешний ресурс через `РаботаВБезопасномРежиме`.
- Долгий ход не вешает клиента: фоновое задание (`ДлительныеОперации` БСП) и опрос `PROCESSING` обработчиком
  ожидания.
- Карточки подтверждения — кнопками «Подтвердить» / «Отменить» прямо в ленте.
- Роль `BPAPI_ЧатПользователь` — кто видит чат; при выдаче через группы доступа БСП роль не слетает
  (суффикс или профиль — проверить).
- **Готово, когда:** на Dev_01 бухгалтер находит контрагента, создаёт реализацию, подтверждает, проводит.

### Этап 3. PDF-вложения (расширение, сервис)
- Кнопка «Прикрепить»: выбор до трёх PDF, проверка размера до отправки, base64 в тело хода.
- Прогресс «Читаю выписку…» до готовности; итог — карточка выписки (сколько создано, есть, отказов) и
  подтверждение проведения.
- **Готово, когда:** выписка из PDF превращается в платёжки и проводится из чата 1С.

### Этап 4. Результаты средствами 1С (расширение, сервис)
- **Ссылка на документ**: созданная реализация, поступление, акт, платёжка — навигационной ссылкой, клик
  открывает форму документа в 1С (сервис отдаёт тип и id, форма строит ссылку).
- **Печать и отчёты**: открывать табличным документом в 1С, а не скачанным PDF; «Сохранить как…» — средствами 1С.
- **Готово, когда:** «распечатай накладную» открывает форму печати, «ОСВ за сентябрь» — отчёт в 1С.

### Этап 5. Выполнение под правами пользователя (сервис, расширение) — вариант Б
- Протокол: ход возвращает `state: TOOL_CALLS` со списком вызовов; форма выполняет их через `BPAPI_Сервис` в
  сеансе пользователя и отправляет результаты; модель продолжает. Белый список и подтверждения — прежние.
- Агент для чата из 1С становится не нужен; идемпотентность — прежняя (`requestId`).
- **Готово, когда:** пользователь без права проведения получает из чата тот же отказ, что в 1С.

### Этап 6. Новые возможности
- **Поступление из PDF накладной поставщика**: распознать строки, сопоставить номенклатуру (поиск с
  транслитерацией), показать карточку с несопоставленным, создать поступление.
- **Акт сверки контрагента из PDF**: сравнить с актом по данным 1С и показать расхождения.
- **«Спросить AI» из формы документа**: команда в формах реализации, поступления, платёжки — открывает чат с
  контекстом этого документа.
- Каждая возможность — отдельной задачей с e2e-сценарием.

### Этап 7. Выпуск
- Тесты: `static_check.py`, `smoke_test.py` (плюс канал 1С), e2e чата от имени пользователя 1С.
- Инструкции: установка (роль, настройки, токен базы), руководство бухгалтера (что можно просить).
- Версия расширения в `Configuration.xml` (аудит E8), API 1.3.0.

## Вопросы, которые решает заказчик

1. Вариант выполнения: А (быстрее выпустить) или сразу Б (права пользователя).
2. Кому доступен чат: всем пользователям базы или по роли.
3. Биллинг и лимиты: считать ходы и вложения на базу или на пользователя.
4. Сеть: у сервера 1С должен быть исходящий HTTPS до `ai.buhprof.kz` (у агента он уже есть).
