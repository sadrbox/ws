## Задачи

| № | Кто | Задача | Статус |
|---|---|---|---|
| T1 | агент + сервис | Блокировка сеансов из среза баз не доходит до реестра: у 111 баз из 111 состояние пустое, хотя полный срез приходит раз в 5 мин. Сервис: писать в журнал, сколько строк среза пришло с `lock`. Агент: проверить, что фоновое чтение блокировок работает и не стоит на паузе после отказа | **сервис — сделано** (`logLockCoverage`: «полный срез баз: строк с блокировкой сеансов»); агент — ждёт |
| T2 | панель | `CLUSTER_DISCONNECT` возвращает `state.locks` (агент R7-А3) — таблица «Блокировки» после разрыва из ответа | **сделано** (`ConnectionsTab`, `echoList(…, "locks")`) |
| T3 | сервис | `AGENT_CANCEL_COMMAND` со снятием процесса возвращает `state.processes` — применять, как у `AGENT_KILL_PROCESS` | **сделано** (`writeState.planWriteState`) |
| T4 | сервис | `IB_APPLY_UPDATE` без эха ставил чтение только расширений; роли могли пропасть (агент R7-А5) — читать и пользователей | **сделано** (`writeState.readsAfter`) |
| T5 | агент → панель | Окно блокировки: при включении «без окна» агент не стирает прежние `from`/`to`; в панели полей окна нет, предупреждение сверяет только `enabled` | агент — проверить и исправить; панель — после агента |
| T6 | панель | Завершённые операции не уходили в историю | **сделано**: без «Истории» «Прогресс» показывает только идущие; число на «Истории» учитывает завершённые |
| T7 | агент (документация) + решение | Контракт `ONEC_AGENT_CLUSTER_CONTRACT.md` не описывает `state.lock`/`infobases`/`config`/`processes`/`publication`/`locks`. Агент объявляет `IB_SELFTEST`, `AGENT_LOG_TAIL`, `AGENT_HEALTH`, `IB_BATCH` — сервис их не знает | ждёт: контракт — сессия агента; команды — решение (вывести в панель или не объявлять) |
| T8 | проверка на сервере | Вживую прогнать E1–E6: блокировка, удаление мёртвой регистрации, загрузка на `_transition`, обновление на копии, снятие процесса, публикация (эхо только IIS) | ждёт |

## Для сессии агента

1. **T1.** Почему в `bases` heartbeat нет поля `lock` (или оно не того вида: нужен объект с
   булевым `enabled`). После перезапуска сервиса число строк с блокировкой видно в его журнале
   строкой «полный срез баз: строк с блокировкой сеансов». Проверить паузу 6 ч после отказа
   фонового чтения и наличие учётной записи, под которой оно идёт.
2. **T5.** Включение блокировки без окна должно стирать прежние `from`/`to` (аргументы `rac`),
   иначе `state.lock` покажет окно прошлой блокировки.
3. **T7.** Описать в контракте блоки эха E1–E6 и `state.locks` у `CLUSTER_DISCONNECT`; по
   `IB_SELFTEST`/`AGENT_LOG_TAIL`/`AGENT_HEALTH`/`IB_BATCH` — либо описать для сервиса, либо не
   объявлять в способностях.
4. **T8** — вместе с администратором, по разделу «Как проверить» в `TASK_AGENT_ECHO_WRITE_COMMANDS.md`.
