# План: новые возможности 1С — что нужно от панели и сервиса

22.09.2026. Парный план к развитию расширения `buhprof_api` (сторона 1С делается отдельно, см. раздел
«Сторона 1С» ниже — он здесь только как контекст). Предыдущие планы:
[PLAN_1C_TASKS_NOTES_2026-09-22.md](PLAN_1C_TASKS_NOTES_2026-09-22.md),
[PLAN_TASKS_NOTES_PANEL_SERVICE_2026-09-22.md](PLAN_TASKS_NOTES_PANEL_SERVICE_2026-09-22.md).

## Зачем

Сегодня расширение умеет 25 операций: реализации, поступления, счета, акт сверки, банк, печать, отчёты и
поиск по четырём справочникам. Разрыв между этим и тем, что спрашивают у помощника, — в трёх местах:

1. **Списков документов нет.** Документ читается только по идентификатору. «Покажи реализации за сентябрь»,
   «какие счета не оплачены» — ответить нечем.
2. **Справочники только читаются.** Нет контрагента — помощник заходит в тупик: завести его он не может.
3. **Нет чисел.** Отчёт возвращает печатную форму; сравнить, сложить и ответить «кто сколько должен» по ней
   нельзя. Единственная числовая операция — сверка выписки по счёту 1030.

Сторона 1С закрывает это новыми операциями. Сервису и панели нужно их принять, дать модели и показать
человеку. Ниже — только работа сервиса и панели.

## Сторона 1С (контекст, делается отдельно)

Новые операции шлюза и их команды агента:

| Операция | Команда | Что делает |
|---|---|---|
| `documents.list` | `LIST_DOCUMENTS` | список документов вида (реализация, поступление, счёт, ПКО, РКО) с отбором: период, контрагент, организация, признак проведения, сумма |
| `counterparties.create` | `CREATE_COUNTERPARTY` | завести контрагента по БИН и наименованию |
| `products.create` | `CREATE_PRODUCT` | завести номенклатуру: наименование, единица, вид |
| `analytics.debts` | `GET_DEBTS` | задолженность по контрагентам на дату: кто должен нам, кому должны мы, просрочка |
| `analytics.balances` | `GET_BALANCES` | остатки по счетам учёта на дату (касса, банк, расчёты) |
| `analytics.turnovers` | `GET_TURNOVERS` | обороты за период по счёту с разрезом |
| `cash.create` | `CREATE_CASH_ORDER` | приходный и расходный кассовые ордера |
| `cash.post` / `cash.unpost` | `POST_CASH_ORDER` / `UNPOST_CASH_ORDER` | проведение кассовых ордеров |
| `diagnostics` | `SELF_CHECK` | самопроверка: связь, токен, права, организации с БИН, версия |

Все читающие возвращают **числа и строки**, а не печатные формы: печать остаётся у `documents.print`.

## Сервис (ai)

**СВ10. Новые команды в белом списке.** Добавить перечисленные `commandType` в реестр инструментов
(`ai/src/tools/registry.ts`) и в контракт агента. Команды идут тем же путём, что нынешние: агент — через
очередь, чат в 1С — через `TOOL_CALLS`.

**СВ11. Инструменты модели для списков.** `list_documents` — вид документа, период, контрагент, признак
проведения, предел. Класс `READ`. В описании явно: это список, а не печать; для печати есть `print_document`.

**СВ12. Инструменты создания справочников.** `create_counterparty` (БИН обязателен), `create_product`. Класс
`WRITE` — значит карточка подтверждения. Защита от выдуманных id здесь не работает (объекта ещё нет), поэтому
проверка другая: БИН — 12 цифр, наименование не пустое.

**СВ13. Инструменты аналитики.** `get_debts`, `get_balances`, `get_turnovers`. Класс `READ`. Ответы компактные:
модели нужны суммы и названия, а не проводки. Ограничить число строк (например, 50) и добавить в ответ
`total`, чтобы модель могла сказать «показаны 50 из 320».

**СВ14. Инструменты кассы.** `create_cash_order` (вид: приход/расход), `post_cash_order`, `unpost_cash_order` —
по образцу реализаций, с `requestId` и подтверждением.

**СВ15. Промпт.** Дописать правила: за списком документов — `list_documents`, а не `run_report`; за суммой
долга — `get_debts`; создавать контрагента только когда поиск ничего не нашёл и пользователь подтвердил.
Без этого модель будет тянуться к отчётам, как привыкла.

**СВ16. Самопроверка базы в панели.** Команда `SELF_CHECK` и кнопка в карточке базы: одним нажатием видно,
что не так на стороне 1С (нет токена, нет организаций с БИН, старая версия расширения, нет прав).

**СВ17. Версия расширения как признак возможностей.** В `GET /ping` уже приходит версия; по ней решать, какие
инструменты показывать модели: на базе со старым расширением `list_documents` только раздражал бы отказами.
Порог — константа рядом с другими версиями канала.

**СВ18. Тесты.** Новые инструменты: сборка payload, отказ при БИН не 12 цифр, ограничение числа строк,
невидимость инструментов при старой версии расширения.

## Панель (frontend)

**ПН6. Самопроверка базы.** Кнопка «Проверить базу» в карточке базы 1С и понятный разбор ответа `SELF_CHECK`:
список проверок с отметками и подсказкой, что сделать. Сейчас такие вещи выясняются по частям.

**ПН7. Версия расширения на виду.** В списке баз — колонка с версией расширения и отметкой «устарело», если
ниже порога из СВ17. Без неё «почему у этой базы нет списков документов» выясняется вручную.

**ПН8. Журнал вызовов чата.** Отдельная вкладка: какие инструменты вызывались, с какой базой, чем кончилось
(успех, отказ 1С, отказ ERP). Сейчас события чата видны только в журнале сервиса, а события агента — в панели;
для разбора жалоб этого мало (дополняет СВ8).

**ПН9. Карточка организации: числа из 1С.** Когда появятся `get_debts` и `get_balances`, показать в карточке
организации задолженность и остатки, обновляемые по кнопке. Это первый случай, когда панель показывает данные
не из ERP, а из базы 1С — решить, кэшировать ли их и на какой срок.

## Порядок

1. **СВ10–СВ11** — списки документов: самая частая нужда, работы немного.
2. **СВ12** — создание справочников: убирает тупики в диалоге.
3. **СВ13 + ПН9** — числа: меняет ценность помощника.
4. **СВ14** — касса.
5. **СВ16–СВ17 + ПН6–ПН7** — эксплуатация: самопроверка и версии.
6. **ПН8** — журнал вызовов.

## Что решить до начала

- **Кэшировать ли числа из 1С в панели** (ПН9). Если да — где и на сколько; если нет — панель ходит в 1С на
  каждое открытие карточки, и при недоступном агенте это заметно.
- **Порог версии расширения** (СВ17): показывать инструменты только с 1.6.0 или мягко — пробовать и отдавать
  отказ 1С как есть.
