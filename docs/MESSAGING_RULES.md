# Куда показывать сообщение: памятка

Три канала, и выбирается канал по ВОПРОСУ, на который отвечает — не по тому, насколько
важным кажется текст.

| Канал | Вопрос | Живёт | Кто снимает |
|---|---|---|---|
| `<Notice />` | «что не так с ЭТИМ объектом прямо сейчас» | пока источник это сообщает | источник |
| `<UIToast />` (`showToast`) | «что только что произошло» | 4–8 секунд | время |
| «Технические сообщения» | «что происходило» | до очистки | человек |

Область — не третий канал, а ПОВЕРХНОСТЬ: она показывает живые сообщения `<Notice />` и
хранит случившиеся события. `<Notice />` сам ничего не рисует (кроме `inline`).

## Правила

1. **Ошибка данных** (валидация формы, 400/409/422/423) → `<Notice />` формы. Не тост:
   человек смотрит на форму, и ответ обязан остаться на экране.
2. **Системный сбой** (нет сети, 5xx, 403, 408, 429) → тост И запись в журнал.
   Не решайте это руками — зовите `routeError` / `reportError` из
   `src/services/errors/route.ts`: он разбирает статус и сам выбирает канал.
3. **Результат действия** («сохранено», «поставлено в очередь») → `showToast`: тост без
   следа. Если результат СОСТАВНОЙ или его спросят позже («создано 12, пропущено 3»,
   «удалено 5 из 7», файл резервной копии) — `notify`: тост коротко, подробности в журнал.
4. **Пояснение о работе экрана** — не сообщение: `<Notice inline>` на месте.
5. **Содержимое модального подтверждения** — `<Notice inline>`: это тело окна.
6. **Пустое состояние списка** — дело списка, не сообщение.
7. **Проверка ДО действия** («сначала выберите файл») — `<Notice />` формы либо
   выключенная кнопка с подсказкой. Тост отвечает не туда, куда человек смотрит.

## Как этим пользоваться в коде

    // В форме: отказ по существу возвращается сюда, системный сбой уже показан и записан.
    setNotices(routeError(e, { source: translate("openingBalance") }));

    // Там, где формы нет (кнопка тулбара, фоновое действие):
    reportError(e, { source: translate("onecTabAgents") });

    // У места вызова есть свой понятный текст — передайте его: он заменит «Request failed
    // with status code 500», когда сервер не объяснил отказ.
    reportError(e, { source: translate("files"), fallback: translate("fileUploadError") });

    // Событие без ошибки статуса — через notify: тост и запись решает он, не автор.
    notify({ severity: "success", source: translate("bankImport"), text: summary });
    notify({ severity: "warning", source, toast: "Загружено 88 из 100", text: fullList });

    // Сбой на клиенте (чтение файла, XLSX, буфер обмена): статуса нет, и reportError
    // показал бы слова библиотеки — текст свой.
    notify({ severity: "error", source, text: translate("fileReadError") });

    // Повторяющееся (опрос, «нет связи»): ключ склеивает повторы в одну запись «×N»
    // на минуту, и тост о повторе молчит.
    notify({ severity: "warning", source, text, scope: paneId, key: "network" });

`notify` (`components/TechMessages/store.ts`) — единственный вход для событий:
`noteNotice`, `addMessage`, `addPaneNotification`, `routeError` — обёртки над ним. Параметры:
`toast` (короткий текст тоста или `false` — без тоста), `ephemeral` (только тост), `active`
(событие ждёт человека и держится актуальным до снятия), `key` (склейка повторов),
`scope` (пейн — для среза «Текущая форма»). Прямой `dispatchEvent("ui_toast")` не нужен.

Новое без тоста область сама объявляет скринридеру (ошибки — срочно); объявлять ещё раз
руками не нужно.

`wide` и `className` у `<Notice />` есть ТОЛЬКО при `inline` — это выражено типом, а не
договорённостью: сообщаемый вариант их не примет.

## Долгая работа

Сейчас реестр операций — `models/OneCAdmin/progress.ts` (`withOp`, `startOp`/`finishOp`), и
пользуется им только панель 1С. Итог операции сам пишется событием в журнал. Перенос реестра
в общее хранилище сообщений и подключение долгой работы вне 1С — задачи M13–M15
(`TASKS_MESSAGING_2026-09-13.md`); до них не заводите для долгой работы собственный
счётчик «идёт…» — это будет третий ответ на один вопрос.

## Журнал — не аудит

Журнал области живёт в localStorage ОДНОГО браузера, хранит события 14 дней и очищается
человеком. Доказательством «что было сделано» он не служит: аудит — серверный
`ActivityHistory` (`auditMiddleware`). Сообщения форм (`<Notice />`) в хранилище браузера не
пишутся вовсе: это текущее состояние, и текст из полей формы не должен оседать на диске.

Разбор и задачи, из которых выросла эта памятка: `TASKS_MESSAGING_2026-09-12.md`,
`TASKS_MESSAGING_2026-09-13.md`.
