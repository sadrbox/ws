# Задача сервису: процессы агента в панели администрирования

> **ВЫПОЛНЕНО СЕРВИСОМ** (сверено по его коду 12 сентября 2026): `AGENT_LIST_PROCESSES`, `AGENT_KILL_PROCESS` и вкладка процессов.
> Документ оставлен как описание контракта — по нему сверяют поля, когда команда
> ведёт себя не так, как ожидается.

Со стороны агента всё готово (сборка от 2026-09-10). Чтобы панель могла показывать и снимать
процессы, сервису нужно добавить две команды в свой whitelist и вкладку в карточку сервера.

## Зачем это нужно

Агент работает чужими руками: `rac`, `ibcmd`, конфигуратор `1cv8`, `webinst`, PowerShell-мост.
Каждый из них — отдельный процесс на сервере 1С. Часть живёт дольше самой команды: конфигуратор
агент НАМЕРЕННО не убивает (прервать `/UpdateDBCfg` посреди работы — оставить базу с наполовину
применённой конфигурацией), а любой процесс переживёт агента, если службу сняли грубо.

В диспетчере задач эти процессы выглядят ничьими: рядом висят `rphost`, `rmngr`, `ragent` самого
сервера 1С, и понять, что чьё, нельзя. Когда один из них зависает, единственным способом
разобраться был вход на сервер по RDP.

## Что уже умеет агент

**Ведёт список того, что запустил сам:** инструмент, что делает, по какой базе, сколько идёт.
Список лежит файлом рядом с настройками и переживает перезапуск, поэтому после падения агента
видно, что осталось с прошлого раза (такие записи помечены `orphan: true` — за ними уже никто
не следит).

**Шлёт список в heartbeat** — полем `processes`:

```jsonc
{ "agentId": "…", "status": "ONLINE",
  "processes": [
    { "pid": 6780, "tool": "1cv8", "what": "выгрузка базы", "base": "buh_alma",
      "ageSecs": 940, "orphan": true },
    { "pid": 4744, "tool": "ibcmd", "what": "extension list", "base": "abdali",
      "ageSecs": 3, "orphan": false }
  ] }
```

**Объявляет способность `agent.procs`** и две команды.

## Что сделать сервису

### 1. `AGENT_LIST_PROCESSES` — что запущено агентом

| Поле | Тип | Обязательность |
|---|---|---|
| — | — | payload пустой |

Ответ: `{ "items": [ … ] }` — те же записи, что и в heartbeat.

`operation: "READ"`, `capability: "agent.procs"`, `role: "admin"`, `requiresBase: false`.

### 2. `AGENT_KILL_PROCESS` — снять процесс

| Поле | Тип | Смысл |
|---|---|---|
| `pid` | число | номер процесса из списка |
| `force` | булево | согласие снять конфигуратор |

Ответ: `{ "ok": true, "note": "…" }`.

`operation: "CRITICAL"`, `capability: "agent.procs"`, `role: "admin"`, `requiresBase: false`.

**Про `force`.** Агент снимает `rac`, `ibcmd`, `webinst` и мост сразу: команда вернёт отказ, и
её можно повторить. Конфигуратор без `force` он не тронет и ответит кодом
`AGENT_PROCESS_UNSAFE` с объяснением: обрыв обновления конфигурации оставит базу непригодной, а
обрыв выгрузки — обрезанный `.dt`. Панель должна показать это человеку и передать `force: true`
только после явного подтверждения — решение за ним, а не за интерфейсом.

**Про безопасность.** Снять можно ТОЛЬКО процесс, который агент запускал сам: номер сверяется с
его собственным списком, чужой процесс он не тронет и ответит `AGENT_PROCESS_NOT_FOUND`. Иначе
одна опечатка в номере остановила бы рабочий процесс `rphost` вместе с сеансами пользователей.

### 3. Вкладка в панели

Таблица: процесс, чем работает, по какой базе, сколько идёт, признак «остался с прошлого
запуска», кнопка «Снять». Записи с `orphan: true` стоит выделять: у них нет команды, которая их
ждёт, и именно они обычно и есть та самая «непонятная нагрузка на сервере».

Обновлять можно по heartbeat (раз в полминуты) — отдельная команда нужна только для кнопки
«Обновить сейчас».

## Как проверить

1. В способностях агента появились `agent.procs`, `AGENT_LIST_PROCESSES`, `AGENT_KILL_PROCESS`.
2. `AGENT_LIST_PROCESSES` возвращает список (на спокойном сервере он пуст — это нормально).
3. Запустить долгую операцию (выгрузку базы) и увидеть её в списке с растущим `ageSecs`.
4. Попытка снять конфигуратор без `force` возвращает `AGENT_PROCESS_UNSAFE` с текстом
   предупреждения; с `force: true` — снимает.
5. Попытка снять чужой номер (например, `rphost`) возвращает `AGENT_PROCESS_NOT_FOUND`.

## Что доступно уже сейчас, без панели

На сервере: `bpapi-agent procs` — таблица, `bpapi-agent procs kill <номер>` — снять. В окне
агента: карточка «Состояние», список процессов с кнопкой «Снять» у каждого.
