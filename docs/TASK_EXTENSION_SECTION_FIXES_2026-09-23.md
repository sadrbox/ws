## А1. Версия расширения показывается из двух разных мест — **высокая**

**Что не так.** В реестр баз (`bases.ext_version`) heartbeat пишет ТОЛЬКО от админ-агента
(`agentRouter.ts`: `if (p.data.bases?.length && me?.serverId && me.role === "admin")`). Срез бизнес-агента
живёт в другой таблице — `agent_bases`. Поэтому:

- раздел «Расширение БухПроф-AI» берёт версию из `agent_bases` и видит все базы с расширением;
- колонка «Расширение» в «Кластеры 1С → Базы» берёт `bases.ext_version` и у баз, которых админ-агент не
  ведёт, показывает «не видели».

**Как ломается.** У клиента без админ-агента (или у базы, которой тот не видит) в списке баз стоит «не
видели», хотя версия известна и показана в соседнем разделе. Это ровно та болезнь, от которой 23.09 лечили
сводку: витрина берёт данные из чужого предмета. Хуже того, «не видели» читается как «расширения нет».

**Что сделать.** Обогащать ответ `GET /v1/onec/bases` версией из среза бизнес-агента: если `bases.ext_version`
пуст, а в `agent_bases` по тому же ключу базы версия есть — отдавать её. Цена — один запрос к срезам на
список баз. Альтернатива (убрать колонку из списка баз и отправлять за версией в раздел расширения) хуже:
версия нужна именно там, где смотрят базы.

Заодно поправить комментарий в `bases/service.ts`: «ext_version заполняет только heartbeat» → «heartbeat
АДМИН-агента; срез бизнес-агента живёт в `agent_bases`».

**Проверка.** Тест сервиса: база, о которой знает только бизнес-агент, приходит в списке баз с версией; база,
о которой не знает никто, — с пустой (не с выдуманной).

## А2. «Обновить» в разделе не обходит кэш срезов — средняя

**Что не так.** `GET /v1/onec/extension-bases` читает срезы с `cached: true`, а кэш живёт 15 секунд
(`agentBases.ts`, `SLICE_CACHE_MS`). Нажатие «Обновить» в первые пятнадцать секунд вернёт ровно те же данные.

**Как ломается.** Человек, который только что попросил клиента обновить расширение, жмёт «Обновить» и видит
прежнюю версию. Дальше он либо ждёт вслепую, либо решает, что обновление не дошло. Кнопка, которая иногда не
обновляет, — хуже отсутствующей кнопки.

**Что сделать.** Разделить обычное чтение и явное обновление: `?fresh=1` (или `cached: false` при
`Cache-Control: no-cache`) читает срезы мимо кэша, панель шлёт его из `onReload`. Кэш остаётся для обычных
открытий раздела — там он и нужен.

## А4. В одном разделе два разных вида таблиц — низкая

**Что не так.** «Доступ AI» и «Базы с расширением» — штатный `Table` (сортировка, поиск, настройка колонок,
действия над активной строкой), «Вызовы чата» — сырая `<table>` без всего этого.

**Как ломается.** Журнал вызовов — самый длинный список раздела, и именно в нём нельзя ни отсортировать по
времени, ни спрятать колонку, ни найти строку поиском. Соседние вкладки это умеют, и разница выглядит
поломкой, а не стилем.

**Что сделать.** Перевести `BaseChatCalls` на `Table` (колонки: дата, база — только в сводном режиме,
инструмент, куда, организация, состояние), без переноса строк. Прочие сырые таблицы панели (карточка агента,
базы агента, здоровье, организации) не трогать: там они — мелкие сводки на несколько строк.
