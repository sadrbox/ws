# Задача агенту: отмена начатой команды и проверка баз по требованию

Две команды, которых не хватает панели. Формат тот же, что у `TASK_SERVICE_DROP_INFOBASE.md`:
сперва зачем, потом контракт, потом чего команда НЕ делает, потом как проверить.

---

## 1. `AGENT_CANCEL_COMMAND` — прервать то, что уже выполняется

### Зачем

Панель умеет отменять только команды в очереди. Ту, что агент уже забрал, остановить нельзя:
она выполняется на сервере 1С, и «отмена» означала бы лишь, что мы перестали ждать ответа.
Кнопка честно гаснет, а человек ждёт.

Цена измерена: команда, вошедшая в зависшую базу, держит место до своего срока (до 15 минут
для чтений, до часов для выгрузки). Параллелизм внутрибазовых команд сейчас равен единице —
значит, за ней стоит вся очередь. Один `ibcmd`, залипший на блокировке, останавливает работу
по всем ста десяти базам.

### Контракт

| Поле | Тип | Смысл |
|---|---|---|
| `commandId` | строка | команда, которую нужно прервать |
| `force` | булево | снимать ли процесс жёстко, если он не завершился сам за 10 с |

`operation: "CRITICAL"`, `capability: "agent.admin"`, `role: "admin"`, `requiresBase: false`.

Ответ: `{ "ok": true, "commandId": "…", "killed": true, "note": "процесс ibcmd 7692 снят" }`
либо `{ "ok": false, "reason": "NOT_RUNNING" }` — команда уже завершилась, снимать нечего.

Результат самой прерванной команды агент отдаёт обычным путём: `status: "FAILED"`,
`error.code: "CANCELED"`, сообщение «Команда прервана по запросу оператора». Это важнее, чем
ответ на саму отмену: сервис закроет запись в очереди и перестанет держать место.

### Чего команда не делает

**Не трогает чужие процессы.** Снимается только тот процесс, который агент сам запустил для
этой команды (у него есть pid в собственном реестре) — как уже сделано в
`AGENT_KILL_PROCESS`: «процесс 9736 агент не запускал — снимать его не его дело».

**Не обещает целостности.** Прерванная посреди работы `ibcmd`-операция может оставить базу в
промежуточном состоянии — для чтений это безопасно, для выгрузки и загрузки нет. Поэтому
панель будет предлагать отмену только для читающих команд, а для разрушающих — показывать,
что остановить нельзя, и почему.

### Как проверить

1. Запустить долгое чтение расширений по большой базе, отменить через 5 с: команда получает
   `CANCELED`, процесс `ibcmd` на сервере исчезает, очередь идёт дальше.
2. Отменить уже завершившуюся команду: `ok: false`, `reason: NOT_RUNNING`, ничего не падает.
3. Отменить чужой процесс (подставить pid стороннего `ibcmd`): отказ, процесс жив.

## 2. `CLUSTER_CHECK_BASES` — проверить наличие баз в СУБД по требованию

### Зачем

Фоновая проверка (сборка от 12.09) присылает `dbMissing` в срезе баз — это уже работает и
закрывает главное. Но она идёт «по пять баз раз в минуту, не чаще раза в сутки на базу»: на
ста десяти базах полный обход занимает сутки, а человек, разбирающийся с кластером ПРЯМО
СЕЙЧАС, хочет ответа сразу.

Сейчас такой ответ достаётся только через `bpapi-agent bases check` на самом сервере — то
есть администратору нужно сначала попасть на сервер.

### Контракт

| Поле | Тип | Смысл |
|---|---|---|
| `baseKeys` | массив строк, необязательно | что проверять; пусто — все базы кластера |

`operation: "READ"`, `capability: "cluster.admin"`, `role: "admin"`, `requiresBase: false`.

Ответ:

```jsonc
{ "items": [ { "key": "aibek", "dbMissing": true },
             { "key": "abdali", "dbMissing": false } ],
  "checked": 110, "skipped": 1,
  "note": "у одной базы не задан пароль СУБД — проверить не удалось" }
```

Поля `dbMissing` — те же три состояния, что и в срезе: `true` (базы данных нет), `false`
(есть), **отсутствие поля** (проверить не удалось; прежнее знание не трогаем). Ответ на
проверку, которую не удалось выполнить, — это не «всё в порядке».

### Чего команда не делает

**Не входит в базы.** Это вопрос к СУБД о наличии базы данных, а не соединение с 1С: сто
десять баз должны проверяться секундами, а не сорока минутами.

**Ничего не меняет.** Команда READ — она только отвечает.

### Как проверить

1. `baseKeys: ["aibek"]` на фантоме → `dbMissing: true`; на рабочей базе → `false`.
2. Без параметров: `checked` равно числу баз кластера, время — секунды, а не минуты.
3. На сервере без пароля СУБД: поля `dbMissing` нет ни у одной базы, `note` объясняет почему.

---

## Что сделает панель, когда это появится

1. `AGENT_CANCEL_COMMAND` — кнопка «Отменить» перестаёт гаснуть для начатых читающих команд;
   в «Прогрессе» отмена становится настоящей, а не «перестали смотреть».
2. `CLUSTER_CHECK_BASES` — кнопка «Проверить все базы» в списке баз: ответ по всему кластеру
   за секунды, фантомы помечаются сразу, без ожидания суточного обхода.
