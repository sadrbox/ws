# Сообщения приложения: Notice, UIToast, «Технические сообщения»

Разбор по факту исходников (2026-09-12) и задачи по разделению. Цифры получены обходом
`frontend/src`, не на глаз.

## Что есть сейчас

| Канал | Мест в коде | Чем является |
|---|---:|---|
| `<Notice />` | 113 (20 `inline`, 93 сообщаются) | сообщение формы: валидация, состояние, отказ по данным |
| `<UIToast />` (`showToast`) | 183 вызова (88 `error`, 47 `success`, 21 `warning`, 9 `info`, 18 без типа) | всплывающее «что сейчас произошло», живёт 4–8 с |
| «Технические сообщения» | одна область + полноэкранный вид | ЕДИНСТВЕННОЕ место показа `<Notice />` + журнал событий |

## Рекомендация: канал выбирается по вопросу, на который он отвечает

    <Notice />   «что не так с ЭТИМ объектом ПРЯМО СЕЙЧАС»  живёт, пока источник это говорит
    <UIToast />  «что только что произошло»                 живёт секунды, исчезает сам
    Область      «что происходило»                          живёт, пока не очистят

Область — НЕ третий канал сообщений, а ПОВЕРХНОСТЬ для двух видов записей: живых сообщений
источников (`<Notice />`) и случившихся событий. Отсюда простое правило владения: живую
запись снимает источник, событие — человек.

### Что куда

1. **Ошибка данных** — валидация формы, бизнес-отказ (422 «серий меньше количества», 423
   «период закрыт», 409 «сначала отключите агента») → `<Notice />` формы. Человек в этот
   момент смотрит на форму, и ответ должен остаться на экране, а не мигнуть.
2. **Системный сбой** — нет сети, 5xx, 403, таймаут → `<UIToast />` И запись в журнал.
   Тост отвечает «сейчас», журнал — «что происходило»; сбой без следа не даёт ответить на
   вопрос «почему полчаса назад ничего не сохранялось».
3. **Результат действия человека** — «сохранено», «удалено», «поставлено в очередь» →
   тост. Если результат СОСТАВНОЙ («12 из 100 не удалось») — тост + запись в журнал:
   разбор по базам за четыре секунды не прочитать.
4. **Пояснение о работе экрана** — не сообщение вовсе: `<Notice inline>` на месте.
   (Исправлено 2026-09-12, коммит 9dcc5e5: пять таких пояснений висели в области вечно и
   не убирались очисткой.)
5. **Содержимое модального подтверждения** — `<Notice inline>`: это тело окна, а не
   сообщение о состоянии.
6. **Пустое состояние списка** — дело самого списка, не сообщение.
7. **Проверка ДО действия** («сначала выберите файл») — `<Notice />` формы либо запрет
   кнопки с подсказкой. Тост здесь — ответ не на том месте, куда человек смотрит.

## Задачи

### M1. Один маршрутизатор ошибок вместо 88 разрозненных тостов (P0)

Сейчас 17 обработчиков `onError → showToast` и **ни один** не различает системный сбой и
бизнес-отказ: 409 «сначала отключите агента» показывается так же, как обрыв сети. Правило
«Notice vs Toast» существует, но исполняется вручную, и потому не исполняется.

Сделать `src/services/errors/route.ts`: `routeError(e, { scope, source })` — по статусу
решает канал (бизнес-отказ → Notice формы, системный сбой → тост + журнал), возвращает
`NoticeItem[]` для формы. Забрать в него `isSystemError`, который сейчас продублирован в
`OpeningBalance/index.tsx` и `DocumentNumberSettings/index.tsx` (`!status || >=500 || 403`).

*Готово, когда:* обработчики форм зовут `routeError`, а не `showToast` напрямую; правило
живёт в одном месте и покрыто тестом на таблицу статусов.

### M2. Системный сбой оставляет след в журнале (P0)

Тост исчезает через 4–8 с, и «что происходило» после него не восстановить. 403 из
перехватчика `services/api/client.ts` показывается тостом и нигде не остаётся.

Добавить в `routeError` запись `noteNotice` для системных сбоев (текст, источник, время).
Тост при этом остаётся коротким, подробности — в журнале.

*Готово, когда:* после отказа сети в области есть запись с временем и источником.

### M3. Валидация ушла из тостов (P1)

Восемь мест сообщают тостом то, что человек должен увидеть на форме: `EgovFillButton`
(«нужен БИН»), `BankStatements/ImportButton` (счёт, файл), `EgovSettingsSection`,
`OneCAdmin/ElementForm` (файл расширения), `ProductImportExport` (файл),
`ProductPriceProcessing` (значение операции, файл).

*Готово, когда:* эти проверки показаны `<Notice />` формы либо выражены запретом кнопки с
подсказкой; тостов с требованием ввода не осталось.

### M4. Дубли «тост + журнал» (P1)

В четырёх местах одно и то же событие пишется дважды дословно (`BaseGroupCommands`,
`shared`, `SessionsTab`, `BasePublication`): человек читает одинаковый текст в двух местах.

Правило: тост говорит КОРОТКО и о факте, журнал — подробности, которые переживут четыре
секунды. Дословное дублирование убрать.

### M5. Длинные тосты (P2)

`DeleteDocumentButton` показывает список мешающих ссылок тостом на 8 с; прочитать такое за
восемь секунд нельзя. Тост: «Удалить нельзя: 3 ссылки», подробности — записью журнала со
ссылкой на объект.

### M6. API `<Notice />` не должен предлагать нерабочее (P2)

`wide` и `className` действуют ТОЛЬКО при `inline`; вне его они молча ничего не делают —
три таких места нашлись и были убраны 2026-09-12. Выразить это типами (union: либо
`inline` + оформление, либо сообщаемый вариант без них), чтобы ошибка не компилировалась.

### M7. Журнал не растёт вечно (P2)

Сейчас ограничение одно — 200 записей (`LIMIT`). События живут, пока их не очистят, и
годовалая запись «нет связи» ничем не отличается от вчерашней. Ввести срок: при загрузке
выбрасывать события старше N дней (настройка, по умолчанию 14).

### M8. Хардкод русских строк в сообщениях (P2)

`ProductImportExport` и `ProductPriceProcessing` шлют тосты литералами («Сначала выберите
файл», «Номенклатуры нет»), минуя словарь. Перевести на `translate`.

### M9. Памятка в кодовой базе (P1)

Правило из этого документа — в `CLAUDE.md`/`docs`, рядом с памяткой «Notice vs Toast»,
одним абзацем и таблицей «вопрос → канал». Без этого следующая форма снова выберет канал
по привычке автора.

## Порядок

M1 и M2 — вместе: маршрутизатор без журнала половинчат. Дальше M3, M4, M9 (дёшево и видно
сразу), затем M5–M8.
