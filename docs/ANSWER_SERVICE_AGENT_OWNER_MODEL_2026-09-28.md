### В2. Один выбор исполнителя
- Правило одно: `agentBases.resolveBusinessTarget`, в сервисе — `AgentService.resolveBusiness(org, orgBin, { baseKey?, preferAgentId? })`.
- Кандидаты — базы всех включённых бизнес-агентов, в которых агент видит организацию с этим БИН, в пределах `maxBases`.
- Если баз несколько:
  1. Явная база или агент диалога.
  2. База, которую организация назвала своей: одобренная за её БИН заявка базы или её действующий токен чата.
  3. Иначе **`BASE_AMBIGUOUS`**: базы с агентами перечислены, в очередь ничего не уходит.
- Агент на связи выбирается только внутри одного уровня. Лежащую свою базу он не подменит копией на связи.
- **Сопоставление правила 2 — пока по имени базы.** Имя уникально только на сервере. Если своих баз под одним именем несколько, это имя в правило не идёт — будет `BASE_AMBIGUOUS`.
- Агенты старых сборок, которые не сообщают организации баз, кандидатами не бывают.
- `pickOnline`, `pickAgentFor`, `visibleTo` и путь «агент фирмы» удалены. Новым путём идут:
  - чат, включая обзорные команды: `GET_ORGANIZATIONS` теперь уходит в базу организации, а не во все базы агента;
  - карточка организации и «Долги и остатки»;
  - статус чата и список агентов пользователя — `servingBin`: агент и только базы с её БИН, без лимита тарифа;
  - самопроверка базы — `resolveForBase`, по одобренным БИН базы реестра.
- `explainUnresolved(bin, label)` различает три случая:
  - `BASE_NOT_SERVED` — БИН нет ни в одной базе агентов;
  - `AGENT_DISABLED` — агент базы отключён;
  - `AGENT_OFFLINE` — агент базы не на связи.

  Несколько баз сообщает сам `resolveBusiness`.

**Сверх задачи — граница между клиентами в чате.** Без привязки агента к организации кандидаты — все агенты BuhProf. Поэтому в чате:
- БИН для выбора базы берётся **только из ERP**. Нет БИН — `ORG_BIN_REQUIRED`.
- Модель назвала другой `organizationBin` — `FOREIGN_ORGANIZATION`.
- `organizationId` в документе должен быть организацией этого БИН в выбранной базе. Иначе тоже `FOREIGN_ORGANIZATION`. Если агент не сообщил id организаций, проверять нечем, решит 1С.
- Ответ `GET_ORGANIZATIONS` сужается до своей организации: в многофирменной базе остальные — чужие клиенты.

### В4. Организация команды
Организация команды — чьи данные затронуты:

| Команда | Организация |
|---|---|
| Бизнес-команда | организация запроса |
| Пакетная, монопольная операция внутри базы, самопроверка | организация базы (`BaseService.organizationOf`) |
| Проверка учёта | первая проверяемая организация базы |
| Кластерная, о самой службе, служебный вход по ключу | `NULL` |

- `organizationOf` берёт организацию из одобренной заявки базы, а если её нет — из действующего токена чата. По БИН из среза организация базы не определяется: у агента кластера среза нет.
- Результат команды видят:
  - пользователи организации команды;
  - сотрудники фирмы с **действующей** связью обслуживания (ERP `service_links`, `active`, срок не истёк);
  - администраторы BuhProf.

  Команду без организации видит вся панель. Особый случай `serverAgent` удалён.
- Держатели очереди в `/queue-stats` отбираются тем же правилом.
